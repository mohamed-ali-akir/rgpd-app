# V2 — Cahier des charges

La V1 aide à exercer son droit à l'effacement pour une page **que l'utilisateur a trouvée**. La V2 :

1. **trouve** les pages qui publient ses données (scanner) ;
2. **vérifie** que l'effacement a vraiment eu lieu après une réponse positive ;
3. couvre les **autres droits** RGPD (accès, rectification, limitation) ;
4. propose un **mode démo** pour une mise en ligne sans risque.

Contrainte : tout doit rester **gratuit** et l'architecture doit **durer** (dépendances externes isolées derrière
des interfaces, comportement prévisible en cas de panne, tests sans réseau).

## Principes d'architecture

| Principe | Application |
|---|---|
| Toute dépendance externe est derrière une interface | `SearchProvider` (moteur de recherche), `ScanSource` (sources du scanner), `HostResolver` (DNS), `MailSender` (V1) |
| Une panne externe ne casse jamais le reste | Chaque source du scanner est isolée : une source en échec est notée dans le rapport, les autres continuent |
| Le serveur ne doit pas pouvoir être retourné contre son réseau (SSRF) | Toute URL lue côté serveur passe par `UrlGuard` : http(s), ports 80/443, adresses IP publiques uniquement, IP figée pendant la requête, redirections vérifiées une par une |
| On respecte les sites | robots.txt respecté (mis en cache 24 h), User-Agent identifiable, délais, taille maximale de page |
| Idempotence | Un même résultat n'est enregistré qu'une fois (empreinte unique par utilisateur) ; un double clic ne crée pas deux demandes (verrou en base) |
| Les règles métier restent dans le back | Le front affiche ; le back décide (statuts, actions possibles, confiance) |
| Données personnelles minimales et chiffrées | Extraits et titres des résultats chiffrés ; purge automatique ; recherche limitée à l'identité du titulaire du compte |

## 1. Scanner

**Sources** (interface `ScanSource`) :
- `CompanyRegistrySource` : API Recherche d'entreprises (gratuite, sans clé) — entreprises dont l'utilisateur est dirigeant,
  paramètres `nom_personne` / `prenoms_personne`. Lien : `https://annuaire-entreprises.data.gouv.fr/entreprise/{siren}`.
- `WebSearchSource` : requêtes `"Prénom Nom"`, `"e-mail"`, `"téléphone"` via `SearchProvider`
  (`searxng` en production, `fake` en démo et en tests, `none` par défaut). Les pages trouvées sont relues (dans la limite
  de robots.txt) pour confirmer la présence des données ; sinon la confiance est réduite.

**Garde-fous** : e-mail vérifié obligatoire ; on ne cherche que l'identité du profil (pas de champ libre) ;
un scan actif à la fois ; 4 scans manuels par 30 jours ; scan mensuel automatique sur option (désactivé par défaut).

**Résultats (`findings`)** : URL, domaine, organisme reconnu, titre et extrait (chiffrés), données détectées, score de
confiance, statut `new / confirmed / rejected / ignored`. L'utilisateur confirme chaque résultat (homonymes). Les
résultats confirmés deviennent des brouillons de demandes en un clic (une demande par page, jamais d'envoi automatique).

**Vérifications guidées** : liens de recherche DuckDuckGo `"Prénom Nom" site:domaine` vers les annuaires, réseaux
sociaux et registres connus, pour ce que l'automate ne peut pas lire.

## 2. Vérification de l'effacement

Quand une demande d'effacement est acceptée : vérification 3 jours plus tard, puis chaque semaine.
- page disparue (404/410) ou données absentes → **effacement vérifié** ;
- données toujours présentes après 4 vérifications → **toujours en ligne** : alerte + plainte CNIL possible
  (nouvelle transition `accepted → complaint`) ;
- page illisible (robots.txt, erreurs répétées) → **vérification impossible** (l'utilisateur vérifie lui-même).

## 3. Autres droits

`kind` : `erasure` (V1), `access` (art. 15), `rectification` (art. 16, avec la correction demandée),
`restriction` (art. 18, avec le motif). Même machine à états, lettres dédiées, fondements de l'art. 17 réservés à l'effacement.

## 4. Mode démo (`APP_DEMO=true`)

Aucun envoi réel (`MAIL_SENDER` forcé à `fake`), moteur de recherche simulé, inscription et Gmail désactivés,
compte de démo réinitialisé chaque nuit (`demo:reset`), bandeau visible.

## API ajoutée

```
GET    /api/meta                              → { demo, demo_email }
GET    /api/scans            POST /api/scans  GET /api/scans/{id}
GET    /api/findings?status=                  PATCH /api/findings/{id}   { status }
POST   /api/findings/requests                 { finding_ids: [] } → brouillons créés / ignorés (avec motif)
GET    /api/guided-checks
POST   /api/requests/{id}/verify              → vérification immédiate (1 par heure)
```

## Tests attendus

Unitaires : normalisation d'URL, garde SSRF, robots.txt, extraction de texte, détection d'identité (accents, ordre
nom/prénom, formats de téléphone), sources avec `Http::fake`. Fonctionnels : scan complet avec une source en panne,
déduplication entre deux scans, décisions, création de brouillons idempotente, vérification d'effacement (chaque issue),
nouveaux droits (lettres en snapshot), mode démo.
